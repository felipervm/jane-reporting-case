Turning Clinic Data into Easier Decisions

An independent product and data study of where recurring clinic-owner questions can still require extra setup — and how I would validate whether those workflows are worth simplifying at Jane.

Product research·Data reasoning·Workflow analysis

The goal was not to invent a feature. It was to follow the strongest public evidence.
01 / Context

I did not start with a solution.

I started with public user feedback about reporting, then checked whether the same friction was visible in Jane's own product documentation. As I researched, I dropped weaker hypotheses when the product already solved them and followed the strongest remaining signal.

Method

Verified customer feedback → official Jane documentation → workflow analysis → hypothesis → validation plan.

02 / Evidence

The feedback that shaped the direction.

These are the public signals that pushed the study toward reusable and more flexible reporting. Each source is linked so the evidence can be checked independently.

Customer signal · Capterra · April 3, 2026

“I wish I could create a report and save it...”

A long-time Jane user described wanting to save a report instead of rebuilding it each time. That directly raised the question of whether recurring reporting setup is a meaningful workflow cost.

The hypothesis

The opportunity is not “more analytics.” It is identifying recurring business questions that are rebuilt often enough that Jane should reduce the steps required to answer them.

03 / Workflow

Where the friction can appear.

Exports are useful and should remain. The question is whether some repeated clinic-owner questions follow the same manual path often enough to justify a lighter native workflow.

01

Ask a recurring question

For example: how did a specific appointment type perform this period?

02

Open the closest report

Use the native filters Jane already provides.

03

Hit a reporting edge

The question needs one more slice or comparison.

04

Export and finish elsewhere

Excel or CSV becomes the place for the extra filter or analysis.

05

Rebuild later

If the question repeats, some of that setup may repeat too.

04 / What I would do at Jane

Validate before building.

I would not start by building a bigger analytics product. I would identify the highest-frequency owner questions, measure the exact manual steps involved, and only then decide which workflows deserve product changes.

The goal is to preserve Jane's clarity and operational simplicity while reducing repeated setup where the evidence justifies it.

01

Map recurring questions

Interview clinic owners around 5–10 questions they answer weekly or monthly and document the current path for each one.

Find real frequency
02

Measure the manual work

Track which questions require exports, extra filtering, spreadsheet calculations, or rebuilding a report state.

Quantify friction
03

Separate edge cases from patterns

Leave rare custom analysis in spreadsheets. Focus only on repeated workflows shared by enough practices to justify a native improvement.

Evidence before roadmap
04

Test narrow improvements

Potential responses could include saved report states, one or two targeted filters, or lightweight interpretation — but only after validation.
